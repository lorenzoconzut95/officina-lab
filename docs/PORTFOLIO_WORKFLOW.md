# Pubblicazione dei prodotti Officina

GitHub è il punto di raccolta delle prove tecniche dei prodotti e dei piccoli esperimenti sviluppati in Officina, secondo l’indicazione del fondatore del 9 novembre 2026.

## Per ogni prodotto

1. Creare una cartella identificabile nel progetto appropriato; usare un repository autonomo quando il codice è davvero separabile.
2. Scrivere un README con problema, destinatario, funzionalità, stato e limiti.
3. Collegare codice originale, specifica, dati sintetici, istruzioni di avvio e test rilevanti.
4. Registrare i controlli realmente eseguiti, indicando data, comando e risultato. Non aggiungere badge verdi o log inventati.
5. Aggiungere screenshot, video o demo solo quando disponibili e verificati.
6. Aggiornare l’indice portfolio e committare una modifica piccola, leggibile e reversibile.

## Evidenze e pubblicazione

- Le specifiche precedenti all’implementazione sono etichettate “progettato”.
- Il software di terzi resta attribuito; un riferimento o fork non dimostra lavoro originale.
- Non pubblicare chiavi, credenziali, database reali, liste contatti o documenti riservati.
- Un repository privato mantiene la sua visibilità finché non viene autorizzato un cambiamento.
- Le attività commerciali, gli invii e la pubblicazione di casi cliente sono azioni separate.
- Un prototipo non diventa “pronto per la produzione” perché compare su GitHub.

Questo documento descrive il metodo di lavoro; non attiva una sincronizzazione automatica né un processo in background.
